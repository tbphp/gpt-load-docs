# 每笔合作记录

在主检出的 `docs/sponsorships/<brand-slug>.md` 保存以下信息。按实际资料填写，未知项写“待确认”；不复制此模板建立虚构订单。读取现有记录后增量更新，保存续费与变更历史。

```markdown
# <品牌> 合作记录

- 合作标识：<稳定 slug>
- 状态：准备中 / 待确认 / 待付款 / 待上线 / 展示中 / 到期待处理 / 下架待发布 / 已下架
- 套餐与加购：
- 席位及核对结果：
- 购买周期、原价、优惠、实付约定、赠送天数：
- 付款状态及用户确认依据：
- 推广链接及 rel 约定：
- 商务联系人：
- 物料位置、中文原稿、最终三语内容的文件位置：
- 技术资料位置及验证结果（仅渠道套餐）：
- 内容确认状态及依据：
- 期望上线日期：
- 各权益实际上线日期和证据：
- 共同计费起点、到期日、含当日口径、时区：
- 提醒日期：<到期后一天，默认 Asia/Shanghai 09:00>
- 提醒 automation id、实际日程、状态、最近核验结果：
- 已提醒时间：
- 涉及仓库、分支、提交、PR 和发布状态：
- 接入位置清单：<逐项列出 README / 官网 / 渠道预设 / 素材，便于准确撤下>
- 下架日期、范围及线上证据：

## 变更历史

- <日期> <接入、修改、续费、提醒或下架的事实和依据>
```

不要把 API Key、测试账号密码、支付凭据原件写入记录、Skill 或自动化 prompt。技术资料只记录非敏感位置和审核结果。官网仓库规则若变化，重新确认记录目录仍被忽略；不得强制提交这些记录。
